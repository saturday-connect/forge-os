# GEMINI.md — Forge OS Context Guide

> For use with Gemini CLI in this repository. Covers the full architecture, build system, key files, and operational playbook.

## What This Repository Is

Forge OS is a documentation-first PDLC and build orchestration framework. The `forge` binary is the user-facing CLI artifact. It manages multiple product projects under `.projects/` and serves a web dashboard for the entire lifecycle.

Three layers:
1. **Source** — `src/`, `desktop/`, `docs/` — edit these
2. **Built artifact** — `./forge` — generated by `python3 src/build_forge.py`
3. **Runtime** — `.forge/scripts/*`, `.projects/<slug>/.forge/scripts/*` — generated by `./forge upgrade`

Never edit `./forge`, `src/dashboard.html`, or any `.forge/scripts/*` file directly. The next build or upgrade overwrites them.

## Build System: How The Compiler Works

`src/build_forge.py` is a pure Python compiler (~260 lines). It reads data files and source templates, generates Python code blocks, and assembles the `forge` binary.

### Inputs

| Source | Purpose |
|---|---|
| `src/data/tools.json` | AI tool and model definitions |
| `src/data/build_steps.json` | Build step definitions and execution order |
| `src/data/stages.json` | Stage → output file mappings |
| `src/data/stage_pipeline.json` | Stage agents, gates, inputs, directory list |
| `src/data/agents/*.md` | Agent prompt Markdown files |
| `src/data/gates/*.md` | Gate prompt Markdown files |
| `src/data/prompts/agent_prompt.md` | AI generation prompt |
| `src/data/prompts/distill_prompt.md` | Distillation prompt |
| `src/runtime/server.py` | Dashboard API server source |
| `src/runtime/build_runner.py` | Build subsystem runner source |
| `src/runtime/constants.py` | Shared runtime constants |
| `src/runtime/forge_cli.py.tmpl` | CLI template |
| `src/dashboard/index.html` + `styles.css` + `scripts/*.js` | Dashboard source |

### All Build-Time Constants

Everything in `src/build_constants.py` — file paths, JSON keys, codegen prefixes, placeholder sentinels, log messages, glob patterns. No magic strings in `build_forge.py`.

### Placeholder Injection

`server.py` and `build_runner.py` contain sentinel comments:
```python
KNOWN_TOOLS = {}  # __FORGE_KNOWN_TOOLS__
STEPS = {}  # __FORGE_BUILD_STEPS__
```
These are replaced with generated Python dicts before the files are embedded into `forge`.

### Template Rendering

`forge_cli.py.tmpl` is rendered with `str.format()`. Injection points are `{UPPERCASE_PLACEHOLDER}` style. Literal Python braces inside the template that should survive rendering unchanged must be doubled: `{{agent}}`, `{{gate}}`.

## Standard Commands

### After any source change
```bash
python3 src/build_forge.py
python3 -m py_compile src/build_forge.py src/runtime/server.py src/runtime/build_runner.py
./forge upgrade
./forge --project "$PWD/.projects/task-flow" upgrade
./forge --project "$PWD/test-projects/saas-todo" upgrade
```

### Restart dashboard
```bash
screen -S forge-dashboard -X quit >/dev/null 2>&1 || true
lsof -tiTCP:8080 -sTCP:LISTEN | xargs -r kill
screen -dmS forge-dashboard ./forge dashboard 8080
curl -sS -o /tmp/forge-dashboard.html -w '%{http_code} %{size_download}\n' http://127.0.0.1:8080/
```
Expected: `200 <non-zero-size>`

### Verify build
```bash
./forge version
./forge
```

## Adding A New AI Model

1. Open `src/data/tools.json`
2. Add the model ID to the relevant tool's `models` array with `id` and display `name`
3. Run `python3 src/build_forge.py`
4. Run `./forge upgrade`
5. Restart dashboard

Both the server-side `KNOWN_TOOLS` and the runtime `_ALLOWED_MODELS` are generated from `tools.json` in the same build. No other files need editing.

## Hot-Deploy

`python3 src/build_forge.py` automatically copies `server.py`, `dashboard.html`, and `constants.py` to every live `.forge/scripts/` directory it can locate:
- `<repo_root>/.forge/scripts/`
- `<repo_root>/.projects/*/.forge/scripts/`
- `<repo_root>/test-projects/*/.forge/scripts/`
- Parent directory siblings: `<parent>/*/.forge/scripts/`
- `~/.forge/scripts/` ← Electron app runtime

`~/.forge/scripts/` is only updated if it already exists (created when Electron runs for the first time).

## Gate System

Gates enforce review quality before downstream stages can run. A gate passes when every generated non-empty file in its mapped directory is reviewed.

```text
context-gate      -> 00-context
prd-gate          -> 01-requirements
design-gate       -> 02-design
architecture-gate -> 04-architecture
engineering-gate  -> 06-engineering
qa-gate           -> 07-quality
release-gate      -> 09-release
marketing-gate    -> 10-marketing
```

Gate prompt files: `src/data/gates/<gate>.md`
Gate instances at runtime: `.forge/12-gates/<gate>.md`

## Security Architecture

- **Thread safety**: three module-level locks (`_state_lock`, `_reviews_lock`, `_index_lock`)
- **Path traversal**: version IDs validated by regex + path prefix check
- **Model allowlist**: `KNOWN_TOOLS` server-side + `_ALLOWED_MODELS` runtime, both from `tools.json`
- **Request cap**: 4 MB max body on all POST and DELETE handlers
- **IPC validation**: type + length checks on all Electron IPC handlers
- **PAT handoff**: atomic write to `~/.forge/_pat_signal` with `0o600` perms; Electron polls, reads, deletes, stores in safeStorage

## Desktop App (Electron)

Wrapper lives in `desktop/` — never `electron/` (causes Node.js module resolution conflict).

Builds three macOS targets: `dmg`, `pkg`, `zip`. The `.pkg` installer runs `desktop/scripts/pkg/postinstall` which auto-clears quarantine — no `xattr` step needed for users who install via `.pkg`.

### Asar Bundle Rule
`desktop/package.json` `files` is an explicit allowlist. Every runtime module must be listed. Omitting a file silently excludes it from the bundle and causes a `Cannot find module` crash at launch.

Current required files: `main.js`, `preload.js`, `auth.js`, `github.js`, `org.js`, `auth-preload.js`, `setup-preload.js`, `auth-window.html`, `setup-window.html`, `assets/**/*`.

### macOS Signing
`desktop/assets/entitlements.mac.plist` must exist. Notarization via `desktop/scripts/notarize.js` (no-op unless Apple secrets are set). User workaround for unsigned builds: `xattr -cr "/Applications/Forge OS.app"`.

## CI/CD

Single workflow: `.github/workflows/build-desktop.yml`

Working directory: `desktop/`.

macOS arm64 and x64 targets built **sequentially** to avoid `.pkg` race condition.

`CSC_IDENTITY_AUTO_DISCOVERY: false` prevents electron-builder crash when `CSC_LINK` is unset.

Tag pushes (`v*`) → GitHub Releases. Non-tag pushes → 14-day artifacts.

## Known Failure Patterns

| Symptom | Cause | Fix |
|---|---|---|
| Dashboard shows stale UI | Source rebuilt but not hot-deployed | `python3 src/build_forge.py` → upgrade all projects |
| Server unreachable | Stale port, server not started, runtime not upgraded | Kill port, restart with screen, verify with curl |
| `Cannot find module './auth'` at Electron launch | Module not in `files` allowlist | Add all required files to `desktop/package.json` `files` |
| `electron not a file` in CI | Directory named `electron/` conflicts with Node.js | Rename to `desktop/` |
| `KeyError: 'agent'` during build | `{agent}` in template consumed by `str.format()` | Use `{{agent}}` in template for literal braces |
| `SyntaxError` in generated `forge` | Raw file slice preserved escaped bytes | Use `ast.literal_eval()` for Python string extraction |
| Empty `CSC_LINK` crash in CI | electron-builder treats empty string as invalid cert | `CSC_IDENTITY_AUTO_DISCOVERY: false` in CI env |
| macOS "app is damaged" | Missing `entitlements.mac.plist` or unsigned app | Create plist; use `.pkg` installer or `xattr -cr` |
| Model not visible in selector | Not in `src/data/tools.json` | Add to `tools.json`, rebuild, upgrade |
| "Unnamed Project" in dashboard | Empty `project_name` + stale Electron server | 3-level fallback + hot-deploy + name backfill on select |
